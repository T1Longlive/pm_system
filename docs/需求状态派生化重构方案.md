## 一、项目概况

- **技术栈**：前后端分离。前端 Vue3 + TS + Element Plus + vxe-table（Vite，端口 5173）；后端 Spring Boot 3 + MyBatis-Plus + MySQL（端口 8080，前缀 `/api`）
- **结构**：`backend/`（Maven，`mvnw.cmd`）、`frontend/`
- **运行**：
  - 后端：`backend/` 下 `mvnw.cmd spring-boot:run`（注意：PowerShell 需先 `$env:Path = "C:\Windows\System32\WindowsPowerShell\v1.0;$env:Path"`，否则 wrapper 报 "powershell not recognized"）
  - 前端：`frontend/` 下 `npx vite`（dev 已在跑）
- **测试账号**：admin / Pm@123456（数据库 `db/init.sql` 初始化）
- **验证命令**：后端 `mvnw.cmd -q compile -DskipTests`；前端 `npx vue-tsc --noEmit`

### 核心领域概念

| 概念 | 定义 |
|---|---|
| 月表 schedule_month | 年+月唯一，PM/管理员创建 |
| 排期行 schedule_row | （月表, 需求, 工种, 负责人）唯一；status=TODO/VOID；planned_effort 工期 |
| 排期格子 schedule_cell | （行, 日期）→ 工作量(0<v≤1, 0.1步进)；日期必须是该月可排班日(WORKDAY/ADJUSTED) |
| **排期组** | （需求, 工种, 负责人）**跨全部月份**的行集合。工期组内共用（任一月改全组同步）；已排 = 组内全部月份格子之和 |
| 需求状态 | PENDING→READY→DEV→TEST→ARCHIVING→ARCHIVED 状态机 + CANCELLED 旁路终态 |
| 排满 | 每个排期组有工期 且 组内跨月格子之和 ≥ 工期 |

**关键不变式**：每个需求全局唯一、每月最多出现一次、可跨月出现；跨月共享需求级数据（编号/名称/工期等），仅每日格子各月独立。删除月排期只删当月行+格子，统计自动跨月重算。

### 现行状态联动机制（问题根源）

`requirement.status` 是**物化字段**，由三套机制维护同步：

1. **保存时即时推进**：saveRow 中排满则 PENDING→READY→DEV 连续触发（通知+日志）
2. **每小时兜底**：advanceBySchedule 扫 PENDING/READY 补推进；DEV→TEST（非QA格子日<今天）；TEST→ARCHIVING（全部格子日<今天）
3. **编辑时回退**：checkScheduleRollback —— READY/DEV 且不再排满时：开发工种(FE/BE/OPS/UI)全灰（无格子日≤今天）→ 回退 PENDING；否则不回退，交给前端拦截

外加：
- **前端退出拦截**：Schedule.vue `onBeforeRouteLeave` → `GET /schedule/incomplete`（非终态 + 未排满 + 开发已开始）非空则强制弹窗阻止跳转
- **已归档只读**：saveRow 挡 ARCHIVED；月视图回传 reqStatus；前端 cellEditable/canCopy/rowStatusInfo/row-archived 样式全链路只读，状态列显示"已归档"
- **需求池**：全部非 ARCHIVED/CANCELLED 需求可选；添加时当月唯一校验 + 工期继承（effortByGroup）
- **连线颜色规则**（ProgressSteps.linkState）：两端取"较高"者，灰 > 绿 > 黄（灰连任意→灰；绿连绿/黄→绿；黄连黄→黄）

### 已确认的漏洞清单（重构动机）

| # | 问题 | 严重度 |
|---|---|---|
| 1 | 退出拦截不区分角色：普通成员进排期页会被 PM 未完成的排期困住（他无权修复） | 高 |
| 2 | 强制排期无逃生门：PM 想取消需求代替补排期，但取消按钮在需求详情页，人被困在排期页 | 高 |
| 3 | 终态校验不一致：saveRow 只挡 ARCHIVED 不挡 CANCELLED；copyRequirementToNextMonth 双终态都不挡 | 中 |
| 4 | **参与人↔排期联动断裂**：需求编辑新增参与人→已有月份不生成排期行（不进排满统计）；移除参与人→其行仍 TODO 计入统计；`VOID` 状态全库无写入（死代码） | 高 |
| 5 | ~~拦截仅前端路由层：F5/关标签页绕过~~ **已修复（2026-09-10）**：Schedule.vue 维护 hasIncomplete 缓存标志（挂载/路由离开检查/fetchView 后同步），beforeunload 同步判断触发浏览器原生确认框兜底 | 低 |
| 6 | TEST/ARCHIVING 无回退路径 | 低 |
| 7 | READY 实为瞬态（排满即连进 DEV） | 极低 |
| 8 | listIncompleteRequirements N+1 查询 | 极低 |

**根因总结**：status 是"排期数据+日期"的物化投影，每个写路径都要记得同步它，漏一处就是一个漏洞（此前"PENDING+开发已开始逃逸拦截"就是这么来的）。

## 三、新方案：状态派生化（已与用户确认）

### 核心思想

> **排期数据 + 日期 = 唯一真相源；需求进度是它的实时投影（纯函数派生），不再"存储后维护"。**
> 只保留两个人工决定落库：归档（archived_at）、取消（cancelled_at/cancelled_by/cancel_reason）。

前端 ProgressSteps 的开发/测试节点颜色本来就是日期实时推导的，已验证此路可行。

### 四个设计原则

**原则 1：stage 为纯函数**（放新组件 `RequirementStageService`）：

```
stage(req, 排期数据, today) =
  cancelled           → CANCELLED
  archived            → ARCHIVED
  无非 VOID 排期行     → PENDING
  存在未排满排期组     → PENDING          // 排期节点黄
  全部非QA格子日 < today:
      全部格子 < today → ARCHIVING
      否则            → TEST
  否则                 → DEV              // 已排满且开发窗口未结束
```

注：READY 不再作为存储阶段（瞬态），仅前端"排期节点"颜色语义保留（排满即绿）。若列表接口需保留 READY 展示，可在 VO 层将"PENDING 且曾排满"区分，或直接砍掉 READY 展示（与用户确认）。

**原则 2：写路径收口为统一对账 `syncStages`**：

```
所有写路径（saveRow/removeRequirement/addRequirement/copyToNextMonth/参与人增删）最后调用：
syncStage(reqId):
  after = stage(...)                       // 纯函数
  if requirement.status != after:
      更新 status（写日志 STAGE_SYNC + 通知参与人）
```

定时任务（每小时）只剩一个职责：捕捉纯时间流逝导致的变化（全量对账非终态需求）。
**删除**：saveRow 中的链式推进代码、checkScheduleRollback、advanceBySchedule 前半段。约 -200 行，新增 ~60 行。

**原则 3：参与人变更并入排期数据**（修漏洞 #4）：

- 新增参与人 → 在该需求**已有排期行的所有月份**自动生成排期行（新组工期为空→自然未排满）
- 移除参与人 → 其全部排期行标 `VOID`（让死代码落地；自动从排满统计/已排合计/日期判定剔除，统计 SQL 已全部带 `status != 'VOID'` 条件，天然兼容）

**原则 4：交互规则纯查询**（退出拦截、节点颜色、已排三态全部读数据不读 status）——`/schedule/incomplete` 现在已经是这个口径，保持。

### 不合理排期的处理边界（已与用户确认）

**两层各司其职：进度如实反映，写入校验拦坏数据。**

| 场景 | 行为 |
|---|---|
| 测试排在开发前 | 系统口径本就是"QA 可与开发并行"，进度图各节点独立显色，如实显示 |
| 有些排有些没排 | 排满=每组格子之和≥工期；任一组不满→排期节点黄；分支卡独立颜色 |
| 排了又取消 | 派生模型自动回退状态，无需回退代码（这正是重构最大收益） |
| 调整日期 | 日期驱动判定下次计算自动跟上，往前挪可能回退状态——如实反映 |
| 排期超量 | 写入校验拦截（saveRow 组内跨月合计>工期 → 400），保留不动 |

**保留的写入校验**（与存储方式无关，全部不动）：格子日期归属月+可排班日、0<v≤1 且 0.1 步进、同人同日跨需求≤1、组内跨月合计≤工期、乐观锁。

**可选增强**（低优先级）：软校验提示"QA 最早格子日 < 开发最早格子日，请确认"，不硬拦。

### 交互漏洞修复（并入本次改造）

- #1：退出拦截仅对**该项目 PM** 生效（`/schedule/incomplete` 按当前用户过滤可修复的需求）
- #2：强制弹窗加"取消需求"逃生入口（或允许跳转到该需求详情页操作取消，取消后不再拦截）
- #3：saveRow 补挡 CANCELLED；copy 补挡双终态
- #5：Schedule.vue 加 `beforeunload`（可选）

## 四、迁移路径（三步，渐进低风险）

**第一步：影子运行（验证口径）**
- 实现 `RequirementStageService.stage()`（纯函数）+ 批量版
- 每小时定时任务：派生值 vs 库中 status 比对，不一致只打 warn 日志不写库
- 跑几天，确认零不一致（口径与现三套机制完全对齐）

**第二步：切读写**
- 列表/详情/月视图/拦截接口全部改读派生值（或改为"写时对账后读库"，实现自选，见下）
- saveRow/removeRequirement/addRequirement/copy/参与人增删接入 `syncStage`
- 删除链式推进、checkScheduleRollback、advanceBySchedule 推进段
- `RequirementServiceImpl` 取消/归档保留（写 status + archived_at/cancelled_at）

**第三步：收尾**
- 参与人↔排期联动落地（原则 3，注意 `applyParticipantDiff` 在 RequirementServiceImpl:645 附近）
- 交互漏洞修复（#1 #2 #3）
- 前端基本不动（status 值域不变，由后端派生返回）；若砍 READY 展示需改 constants/requirement.ts 与筛选

### 实现决策（已定）

- **status 字段保留落库**（不删列）：写路径对账后仍写 status，读路径直接读库——既消灭"忘记同步"（对账统一收口），又避免每次读都全量派生的查询开销。stage 纯函数是唯一写 status 的来源（取消/归档除外）。
- 派生所需数据查询可复用现有 Mapper：`countNotFullRows`、`selectDevReqIdsAllPassed`、`selectTestReqIdsAllPassed` 的口径，建议新加一条**批量按需求聚合**的 SQL（一次查出所有非终态需求每组 pe/total/max_day，避免 N+1，参考 countNotFullRows 的写法做 JOIN 聚合）。
- 通知与日志沿用现有：NotifyTypes.REQ_STATUS_CHANGED、writeLog(biz_type=REQUIREMENT)。

## 五、工程约定与教训（必读）

1. **编辑可能未落盘**：本项目多次出现 Edit 工具返回成功但磁盘未写入（尤其同文件并行多 Edit）。**每次编辑后必须用 Grep 验证磁盘内容再编译。**
2. mvnw 需要 PowerShell PATH 前缀（见"运行"）。
3. 后端改代码后必须重启才生效（曾因未重启导致前端跳转报错的"假 bug"）。重启流程：`Get-NetTCPConnection -LocalPort 8080` 找 PID → Stop-Process → 后台 `mvnw.cmd spring-boot:run` → 等端口 + admin 登录实测接口。
4. 表格样式硬约束（用户强偏好）：表文字黑色/周末灰、斜纹加深灰底(#cdd3dd/#aab4c4)、无行 hover、表头冻结 #a0cfff 加粗、外层无滚动条、已排格无底色仅深蓝粗字(#1b4f8a)、编辑透明仅底部蓝下划线、前 9 列水平垂直居中、日列 30px/负责人 80px/工种 80px/优先级 50px、编号|需求名称|项目|策划|优先级 合并、工种/负责人行级不合并。
5. 代码注释全部中文；服务接口 javadoc 即口径文档，改逻辑必须同步改注释。
6. Bug 管理硬约束：仅 PM 和管理员可归档 bug、所有用户可删 bug、bug 字段可空、重开已归档 bug 清空处理/验收进度。
7. 通知/日志口径：状态变更通知全部参与人（去重）；排期修改仅通知该行负责人（仅格子实际变化时）。

**实施结果（已实测）**：
- 启动对账后库中无 READY 存量（PENDING/DEV/ARCHIVED 分布正常）
- 端到端验证：加入月表→PENDING；全部排满→直接派生 DEV（无 READY 中间态）；清空任一行→自动回退 PENDING；
  移除月排期→PENDING，数据复原
- 后端 mvnw compile 通过；前端 vue-tsc 通过；admin（PM）实测 /schedule/incomplete 返回空（无未排满+已开工案例）

**衍生口径注意**：
- 派生模型下「部分删除导致未排满」即使开发已开始也回退 PENDING（旧机制保持 DEV）——退出拦截不读 status，仍会拦截，行为一致
- QA-only 需求（无非 QA 行）排满后直接进 TEST/ARCHIVING 窗口判定（旧机制卡 DEV）
- 定时对账不写操作日志（operator_id 非空约束），用户触发写 STAGE_SYNC 日志
